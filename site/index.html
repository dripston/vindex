The blind spot

        
Three bugs that sail through an English eval suite.

        
Whoever reviews your outputs probably reads Hindi fine, so these look correct. They aren't — not for the user who typed them, and not for the judge scoring them.

      

      

        

          
Wrong script

          
Mumbai kahan hai?

          
मुंबई महाराष्ट्र में है।

          
FAILscript_mismatch — the user typed in Roman script; the bot replied in Devanagari they may not read.

        

        

          
Misread by the judge

          
समुद्र तल पर पानी किस तापमान पर उबलता है?

          
Judge reasoning: “The question asks about the boiling point at the sea floor…”

          
FAILmisread_detected — समुद्र तल means sea level. A correct answer was about to be scored 0.

        

        

          
Similarity that can't discriminate

          
cosine(gold, answer) = 0.99

          
cosine(gold, wrong answer) = 0.99

          
REFUSEDlow_discrimination — vindex won't hand you a verdict from an encoder that scores everything the same in your language.

        

      

      

        
4 in 5

        
Hinglish questions answered in Devanagari by a model told to “reply in the user's language.” One line of prompt fixed it to 100% — but only a check that runs on every response would ever have noticed.

Four checks

        
Start free. Add a judge when you need one.

        
Every check returns the same MetricResult — a score, a pass/fail, a stable label to branch on, and a one-line reason you can read in a red CI log.

      

      

        

          

            

            
freeno LLMno reference

          

          
script_adherence

          
Did the reply come back in the script the user wrote in? Catches Devanagari answers to Hinglish questions, English answers to Tamil ones, and emoji-only non-answers.


from vindex import script_adherence

r = script_adherence("Mumbai kahan hai?", reply)
r.label  # "script_mismatch"

        

        

          

            

            
freedeterministicany judge

          

          
check_trace

          
Reads your LLM judge's reasoning and flags it when it misread an ambiguous Hindi term — समुद्र तल as “sea floor”, उत्तर as “answer” instead of “north”. Ships with a 69-term dictionary; bring your own.


from vindex import check_trace

r = check_trace(question, judge_reasoning)
r.label  # "misread_detected"

        

        

          

            

            
local encoderneeds golden · hi · hinglish

          

          
calibrated_similarity

          
Embedding similarity with thresholds calibrated per encoder and language, not a magic 0.5. Where an encoder can't tell right from wrong in your language, it says so instead of guessing.


from vindex import calibrated_similarity

r = calibrated_similarity(gold, answer, language="hi")
r.label  # "similar" | "dissimilar" | "low_discrimination"

        

        

          

            

            
LLM judgereference-freepinned model

          

          
indic_judge

          
An LLM judge with a Hindi rubric that knows Romanized Hindi isn't an error. Conservative by default, temperature 0, and the judge model is recorded in every result. Groq, OpenAI, Anthropic, or 100+ providers via LiteLLM.


from vindex import indic_judge
from vindex.judge_model import OpenAIJudge

r = indic_judge(question, answer, judge=OpenAIJudge())

        

      

    

  


  
  

    

      

        
Fits your workflow

        
One command in CI. Or one line in the eval suite you already have.

        
Point vindex run at a JSONL, JSON or CSV export — column names from DeepEval, promptfoo and Ragas are recognized as-is. It exits non-zero when a pass rate drops, and writes a summary straight into your GitHub Actions run.

      

      

        

          
          
          
          
          
          
        


# cases.jsonl — one object per line
# {"prompt": "Mumbai kahan hai?", "response": "...", "gold": "...", "trace": "..."}

$ vindex run cases.jsonl                    # script_adherence (+ check_trace on rows with a trace)

$ vindex run cases.jsonl --fail-under 0.95 -o report.json
$ vindex run cases.csv -f markdown > report.md

@pytest.mark.parametrize("prompt", [

Built for production

        
Boring where it matters.

      

      

        

          
          
Deterministic by default

          
Two of four checks are pure functions. The judge runs at temperature 0 and stamps its exact model id on every result.

        

        

          
          
Fails loudly, not silently

          
Unreliable encoders, emoji-only replies and same-family judges get their own labels and warnings instead of a quiet pass.

        

        

          
          
Reasons humans can read

          
“prompt is code-mixed; response in devanagari, not Roman script.” Not “score below threshold”.

        

        

          
          
Tiny core

          
One dependency for the free checks. Encoders and LLM SDKs are opt-in extras, imported only when you use them.

        

        

          
          
Verify it on your model

          
The labelled benchmarks behind the shipped thresholds come with the package. Re-calibrate on your encoder or judge in a few lines.

        

        

          
          
Typed and tested

          
Strict mypy, a frozen result dataclass, and a test suite that runs on every push. MIT licensed.
